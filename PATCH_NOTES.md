# DJMAKER — патч 0039: массовое добавление и подбор продолжения сета

База: `main` / `ac46f16` (0038a). Накладывать поверх 0038a.
Зависимости, `pyproject.toml` и схема SQLite не изменены. Повторный `pip install`
и миграция базы не нужны.

## Массовое добавление в плейлист

В каждой строке медиатеки появился флажок выбора. Выделение сохраняется при поиске
и повторной отрисовке списка. Кнопка «В плейлист: N» позволяет:

- добавить выбранные треки в существующий плейлист;
- создать из выделения новый плейлист;
- снять всё выделение отдельной кнопкой;
- сохранить текущий порядок медиатеки при добавлении;
- пропустить треки, которые уже есть в выбранном плейлисте.

Пакетная операция выполняется одной SQLite-транзакцией. Если плейлист или хотя бы
один трек больше не существует, частичного добавления не происходит.

## Подбор продолжения DJ-сета

В разделе «Плейлисты» появилась кнопка «Подобрать продолжение». В диалоге можно
выбрать опорный трек текущего плейлиста, строгость и несколько кандидатов, после
чего добавить их в показанном порядке.

Режимы:

- «Строгий»: разница темпа до 3% и та же, параллельная или соседняя Camelot-тональность;
- «Сбалансированный»: разница темпа до 6%, допускается энергетический переход;
- «Свободный»: разница темпа до 12% либо близкая гармоническая совместимость.

DSP BPM/Key имеют приоритет над файловыми тегами. Для темпа учитываются обычное,
двойное и половинное значения. Из результатов исключаются опорный трек и все треки,
которые уже находятся в плейлисте. Для каждого кандидата показывается объяснение:
разница BPM, преобразование темпа и переход Camelot. Подбор локальный и не меняет
музыкальные файлы, теги или данные анализа.

Алгоритм является детерминированной технической рекомендацией, а не гарантией
идеального художественного перехода. Итоговый переход следует проверить на слух.
За один поиск рассматривается до 10 000 треков и показывается до 50 кандидатов.

## Установка и проверка

1. Полностью остановите DJMAKER.
2. Распакуйте ZIP в корень проекта с заменой файлов, сохранив относительные пути.
3. Выполните `compileall` и полный набор тестов.
4. При результате `Ran 200 tests` / `OK` запустите приложение.

Резервная копия базы для этого патча не обязательна: структура БД не меняется.
Музыкальные файлы и их теги установка патча не затрагивает.

## Проверки

Linux, Python 3.14.7, Flet 0.86.5:

- целевые тесты плейлистов, UI и алгоритма: 34 теста, OK;
- полный regression: 200 тестов, OK;
- `compileall`, `git diff --check`, состав ZIP и SHA-256;
- повторное наложение архива на чистый `ac46f16` и полный regression.

Проверены порядок и дедупликация пакетного добавления, атомарный откат при ошибке,
создание плейлиста из выделения, управление выделением в UI, добавление выбранных
рекомендаций, приоритет DSP, строгий/сбалансированный/свободный режимы, соседние и
параллельные Camelot-переходы, переход 12↔1, половинный/двойной BPM, исключения и
стабильное ранжирование.

Native GUI Windows/macOS, системный Drag&Drop, реальное воспроизведение и
desktop-build в этой среде не запускались. На Windows проверьте через
`flet debug windows .`: выбор нескольких треков → добавление в новый и существующий
плейлист → «Подобрать продолжение» → смена опорного трека и режима → прослушивание
и добавление нескольких рекомендаций.
