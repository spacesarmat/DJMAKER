# DJMAKER — патч 0038: плейлисты и экспорт с музыкальными файлами

## Исправление 0038a

В Windows-тестах чтение созданных UTF-8 плейлистов теперь всегда выполняется
с явной кодировкой `utf-8`. Ранее один тест использовал системную кодировку
Windows (`cp1251`) и завершался с `UnicodeDecodeError`, хотя приложение и сам
экспорт работали правильно. Код приложения, схема БД и музыкальные файлы этим
исправлением не изменяются.

База: main 9a5dc2e (0037). Накладывать поверх 0037.
Зависимости не изменены. Повторный pip install не нужен.

## Использование

В навигации появился раздел «Плейлисты»:

- создание, переименование и удаление плейлиста;
- добавление трека: меню ⋮ в строке медиатеки → «Добавить в плейлист»;
- создание нового плейлиста прямо из диалога добавления трека;
- повторное добавление одного трека в тот же плейлист не создаёт дубликат;
- ручной порядок: стрелки вверх/вниз рядом с треком;
- кнопка прослушивания через существующий плеер;
- удаление из списка сохраняет запись медиатеки и оригинал на диске;
- количество треков, общая известная длительность и число неизвестных длительностей.

Плейлисты и порядок хранятся в SQLite и сохраняются при перезапуске.
Порядок плейлиста не зависит от сортировки медиатеки.
Переименование/перемещение файла через DJMAKER отражается в плейлисте по ID трека.
Если запись трека удаляется из БД (например, после сканирования отсутствующего файла),
соответствующая связь удаляется из плейлистов. При обнулении БД удаляются и плейлисты.

## Два варианта экспорта

Обе кнопки предлагают выбрать родительскую папку и создают в ней новую папку
с названием плейлиста. Если имя занято, добавляется номер — существующее не затирается.

1. «Экспорт .m3u8»: UTF-8 плейлист с абсолютными ссылками на исходные файлы.
   Музыка не копируется. Ссылки действуют пока исходные файлы доступны по тем же путям.
2. «Экспорт с файлами»: .m3u8 + папка Music с копиями музыкальных файлов.
   Ссылки внутри .m3u8 относительные. Переносите всю экспортную папку целиком.
   Копирование побайтовое, без перекодирования; встроенные теги и обложки сохраняются.
   Имена копий имеют порядковые префиксы, поэтому одинаковые имена не конфликтуют.

Экспорт использует снимок порядка/названий/путей на момент начала задачи.
Он выполняется в фоне и отображается в разделе «Задачи».
Есть остановка/возобновление и отмена. Возобновление начинает экспорт снимка заново;
незавершённая папка удаляется при остановке, отмене и ошибке.
Если её удалить не удалось, ошибка содержит путь для ручной проверки.

При отсутствии исходного файла, ошибке записи или изменении файла во время копирования
экспорт завершается ошибкой, а не выдаёт неполный сет за готовый.
В готовый результат входят сами аудиофайлы и M3U8. Сторонние sidecar-файлы,
папки с обложками и базы/форматы Rekordbox, Serato, Traktor не экспортируются.
Совместимость импорта M3U8 в конкретный плеер проверяется на целевом приложении.

## Установка и миграция

1. Полностью остановите DJMAKER.
2. Сохраните копию заменяемых исходников и library.sqlite3 перед первым запуском.
   Стандартный Windows-путь: %LOCALAPPDATA%\DJMAKER\library.sqlite3.
   При заданном DJMAKER_DATA_DIR база находится в этом каталоге.
   Для работающей с WAL базы используйте SQLite backup API либо копируйте
   файлы базы только после полного завершения приложения.
3. Распакуйте ZIP в C:\Users\ANDYBUM\PycharmProjects\DJMAKER.V.2 с заменой,
   сохраняя относительные пути src, tests и PATCH_NOTES.md.
4. В активном окружении проекта выполните:

```powershell
python -m compileall -q src tests
python -m unittest discover -s tests -v
```

5. При OK запустите `flet debug windows .`.

При первом запуске схема SQLite автоматически обновляется с 4 до 5.
Существующие треки сохраняются; обнуление или повторное сканирование не требуется.
Для отката после миграции нужно восстановить и исходники 0037, и резервную БД v4.
Код 0037 не откроет БД v5. Новые плейлисты при восстановлении старой БД будут потеряны.

## Проверки

Linux, Python 3.14.7, Flet 0.86.5:

- База 0037: 157 тестов, OK.
- 0038: 184 теста, OK.
- После распаковки ZIP на чистую базу 0037: 184 теста, OK.
- compileall, git diff --check, состав и CRC ZIP, SHA-256.

В тестах используются настоящие временные SQLite-базы и файловое копирование.
Проверены миграция v4→v5 и повторное открытие, сохранность исходных треков,
атомарное создание с первым треком, отсутствие дублей, порядок и каскады,
M3U8 с относительными/абсолютными путями, одинаковые имена, перенос экспортной папки,
совпадение байтов, отмена, пауза/возобновление, ошибка записи и изменение исходника.
Обработчики Flet проверены с настоящей БД; системный выбор папки заменён в тестах.

Native GUI Windows/macOS, системные диалоги, воспроизведение, Drag&Drop и desktop-build
в этой среде не запускались. После установки проверьте интерфейс на своём ПК:
создать список → добавить 2–3 трека → переставить → экспортировать с файлами →
открыть M3U8 в целевом плеере → перенести папку и открыть снова → перезапустить DJMAKER.
